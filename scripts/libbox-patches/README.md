# Android libbox build

Run `bash scripts/build-libbox.sh [local sing-box repository]` from the Polaris repository. The default local object source is `~/Code/sing-box-v1150a8`; the builder never changes that repository. It creates a fresh detached checkout under `~/Code`, applies the hash-checked patch, runs the lifecycle regressions, and binds all four Android ABIs.

`src-tauri/core-manifest.json` owns the version. `source-manifest.json` pins its official tag's full commit, Go 1.25.5, SagerNet gomobile/gobind v0.1.13, JDK 17, NDK 30.0.16138531-beta3 (SDK directory `30.0.16138531`), API 24, and the upstream feature tags. A source/tag mismatch, missing cached dependency, different toolchain, or changed patch hash stops the build. `LIBBOX_GO`, `JDK17`, `ANDROID_HOME`, and `LIBBOX_NDK_HOME` can select installed paths; their versions are still checked. The app/Rust `ANDROID_NDK_HOME` does not select libbox's toolchain.

NDK 27.3.13750724 rejects the pinned Cronet arm64 static archive with `unknown relocation (315)`. The cached NDK 30 builds the unchanged upstream dependencies; explicit 16K linker flags are retained. The builder validates every packaged native library's PT_LOAD alignment and dynamic dependencies, every libbox ABI's Go version and feature tags, and the generated Java signatures before replacing `src-tauri/gen/android/app/libs/libbox.aar`. `build-receipt.json` records those observations and hashes. No legacy variant is produced, and no APK is built or installed by this script.

The transient patch adds `Libbox.newTransientCommandServer(handler, platform)`. Start it with `startOrReloadService(config, OverrideOptions())`; `start()` rejects command-listener creation. The host skips shared configuration snapshots, OOM/power recorder creation, draft promotion, and replacement of the process default logger. Close it with `closeService()` followed by `close()`. Its service uses the normal `StartedService` path, so the caller must still provide separate configured cache/state/API paths and must not call process-global `Libbox.setup()` for each transient session.

The interface binding patch adds the explicit gomobile platform method `bindInterfaceControl(int fd, String interfaceName) throws Exception`. On Android, both outbound `bind_interface` and route `default_interface` attach the same per-socket callback to TCP dialing and UDP listening. The Android caller must bind the requested current physical Network and protect its socket when its VPN is active. Missing callbacks, closed descriptors, unavailable networks and binding failures are errors; no default-network fallback is added. Other platforms keep their existing interface binding, and automatic Android routing keeps its existing path. The separate optional adapter interface avoids changing desktop adapters. `CheckConfig` supplies a construction-only stub whose socket callback fails if called.

The clash mode patch makes mode reads atomic and serializes mode changes with DNS cache clearing and cache persistence. An explicit `experimental.clash_api.default_mode` wins at startup over a stale cached mode; when it is absent, the existing cache restore behavior remains. The builder runs the clash mode transition tests under Go's race detector before binding the AAR.

The receipt establishes provenance for the newly built artifact. `-buildvcs=false` means an older AAR's Go build info alone cannot establish its exact source commit.

The construction validation patch adds `Libbox.checkConfigWithResult(config, requestID, timeoutMillis)` and seven read-only `ConfigValidationResult` getters. Match `getRequestID()`, the exact UTF-8 config's SHA-256 from `getConfigDigest()`, and `getContractVersion() == "polaris-validation-v1"` before consuming the separate `Accepted|Rejected|InternalFailure` validation and `NoConstruction|DisposedExact|CleanupUnknown` cleanup values. Parse rejection preserves the original `decode config:` message and reports `NoConstruction`. Every constructed box currently reports `CleanupUnknown`, even when its observed cleanup succeeds. `DisposedExact` is reserved and disabled.

`box.New` records top-level resources in an explicit rollback scope and cancels on partial failure or panic. Ordinary New preserves prompt error and panic propagation while the failed scope retains asynchronous cleanup; it supplies no disposal receipt. `NewWithConstructionReport` waits for observed rollback and can block on a cleanup callback. Successful construction transfers resources to the returned box and separately disposes replaced construction objects. This common path covers main, transient and validation construction; it does not establish an exact cleanup certificate for main/transient lifecycle close. Validation never calls Start or PreStart. A timeout from 1 through 60000 ms returns an immutable `CleanupUnknown` receipt while its canceled worker continues cleanup; there is no late callback or receipt promotion.

The six managers use explicit `DisposeConstruction` capability for each child without a successful runtime Start. Unknown types report unknown disposal and skip ordinary Close, including unstarted TUN autoRedirect; manager initialization is never child ownership evidence. Endpoint delegated Start records the successful child back to its owning manager. Close, Remove, replacement and object-plus-error factory paths share this rule. SSMAPI, CCM and OCM construction disposal does not save cache/usage files; ordinary persistence requires successful loading and runtime admission. Delayed usage saves serialize with final Close and cannot write after persistence admission closes. Legacy CheckConfig keeps returning only its original validation error; independent cleanup errors appear in the new result.

Scope termination and ownership transfer share one state lock. TransferAll detaches residual replacement/failed-constructor cleanup into a batch that the current operation actually drains; published child resources are handled separately. A terminated context cannot append cleanup or errors to its former scope. Late DeferCleanup/Replace runs under the current operation, and rejected Register tokens retain caller ownership, require explicit rejection handling and cannot Transfer. Each manager Create uses a local factory scope, handing residual work only to an active parent construction scope or draining it locally. This preserves ordinary New error/panic propagation and prevents late partial objects from being treated as Box-owned resources. SSM cache saving and disposal now share the cache mutex for admission, encoding, writing and shutdown. Race tests exercise terminal-context factories, Register/Transfer/Close contention and real SSM/CCM/OCM Save calls blocked at file acquisition; none of these observations enables exact cleanup.

The pinned sing-tun dependency still has unowned rule deletion inside partial Start and startup-wide stale cleanup. This conservative patch does not repair those runtime paths. Independent evidence and the dependency design remain separate review items; no production dependency patch or replace is included.

Exact cleanup remains blocked on a complete constructor and task-quiescence audit for every enabled registry implementation and platform branch. Successful child Close, elapsed time, context cancellation, the rollback stack, and a later native return each remain insufficient evidence by themselves. The builder runs construction fault injection, real cache/usage preservation and lifecycle regressions with the Go race detector, including the default registry and independent/combined CCM and OCM build tags. It verifies the result's Java getters and absence of setters and records `exactCleanupEnabled: false` in the AAR build receipt.
